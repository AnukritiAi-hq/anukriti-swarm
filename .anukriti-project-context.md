## What this project is

**Anukriti Swarm** is a distributed multi-agent genomic intelligence system for population-aware pharmacogenomic reasoning. Core mission:

> **"Population-aware pharmacogenomic risk analysis before clinical trials."**

The platform decomposes pharmacogenomic reasoning into specialized, verifiable agent tasks: population context → pharmacogene reasoning → evidence retrieval → deterministic verification → explainable risk synthesis. Population is a **first-class reasoning dimension**, not metadata.

Scope firewall — the platform is NOT:
- a generic RAG chatbot
- a generic healthcare assistant
- an EHR system or clinical copilot
- a document search engine
- a GraphRAG framework
- an LLM-as-judge system

Every layer enforces this boundary through closed enums at the type boundary. Drift into generic territory requires a deliberate code change, never a runtime configuration.

### 4 deterministic rule tables

**SufficiencyDecisionEngine — 12 rules → 7 decisions**
```
R1  hard conflict or CONFLICT_FREE MISSING  -> BLOCK
R2  PHENOTYPE MISSING                        -> BLOCK
R3  RECOMMENDATION MISSING                   -> BLOCK
R4  provenance incomplete                    -> ABSTAIN
R5  POPULATION MISSING                       -> ESCALATE
R6  CPIC MISSING                             -> REQUEST_MORE
R7  ALLELE MISSING                           -> REQUEST_MORE
R8  RECOMMENDATION UNCERTAIN                 -> DOWNGRADE
R9  POPULATION UNCERTAIN                     -> DOWNGRADE
R10 any other UNCERTAIN                      -> DOWNGRADE
R11 CONFLICT_FREE UNCERTAIN (soft only)      -> PASS_WITH_CAVEAT
R12 all clean                                -> SUFFICIENT
```

**SetLevelEvidenceVerifier — 10 rules → 5 verdicts (SURE-RAG-style)**
```
V1  named AVOID/USE invertor -> REFUTED
V2  other hard conflict      -> CONFLICTING
V3  PHENOTYPE missing        -> INSUFFICIENT
V4  RECOMMENDATION missing   -> INSUFFICIENT
V5  other missing facet      -> INSUFFICIENT
V6  empty KG path bundle     -> UNCERTAIN
V7  POPULATION uncertain     -> UNCERTAIN
V8  other uncertain facet    -> UNCERTAIN
V9  CONFLICT_FREE uncertain  -> UNCERTAIN
V10 all clean                -> SUPPORTED
```

**UncertaintyScoringEngine — 9 rules → 4 tiers**
```
U1 hard conflict                 -> UNSAFE
U2 missing non-conflict facet    -> HIGH
U3 POPULATION uncertain          -> HIGH
U4 empty KG path bundle          -> HIGH
U5 >=2 uncertain facets          -> HIGH
U6 CONFLICT_FREE uncertain       -> MODERATE
U7 exactly 1 non-core uncertain  -> MODERATE
U8 KG path bundle with 1 path    -> MODERATE
U9 otherwise                     -> LOW
```

Tier → action: `UNSAFE→BLOCK`, `HIGH→REQUEST_MORE`, `MODERATE/LOW→PROCEED`.

```
EUROCENTRIC_IMBALANCE      target non-EUR + target evidence=0 + EUR evidence>0
ANCESTRY_SCARCITY          target allele count / max < 0.5 (default)
UNSUPPORTED_EXTRAPOLATION  POPULATION UNCERTAIN + target has 0 KG freq data
```

## Key design conventions (applies across sessions)

### Closed enums at the type boundary
Every cross-module contract passes a closed enum, never a string. Extension requires a code change. This is the mechanism that prevents scope drift into generic territory.

### Micro-commits
Each session averages 10-22 commits, each independently verified with an in-commit smoke test. Commit messages document scope / contract / smoke-test results / regression evidence. This makes incremental review possible.

### Deterministic core vs generative edge
- Deterministic (everything in `core/evidence_sufficiency/`, `knowledge_graph/`, `core/verification/`, `rules/`, `guidelines/`): no LLM, no randomness, no temperature. Same inputs produce same outputs.
- Generative (`narrative/`, `agents/orchestrator/gemini_orchestrator.py`): boundary-guarded, runs only after deterministic verification + sufficiency clears it.

### Scope collapse with documentation
When a brief asks for N top-level directories where M of them would hold 1-2 files each, we collapse to a smaller number of coherent top-level packages with internal subpackages, and pin the rationale at the top-level `__init__.py`. Same pattern was used in session #5 (5→4) and session #6 (7→2 top-level + 5 subpackages).

### Off-by-default via constructor argument
New capabilities integrate via explicit constructor args defaulting to `None`, not via feature flags. This makes the off-by-default contract self-documenting and reviewable.

### Frozen audit records with `.record_*` builders
`VerificationTrace`, `ClaimCoverageAnalysis`, `EvidenceSufficiencyTrace`, `RetrievalStrategyResult` are all frozen dataclasses. Updates return a new instance preserving identity (claim_id / trace_id / correlation_id). This gives us replay safety and explicit audit trails.

### Demo signature preservation
After every commit, all flagship demos are re-run. Their output signatures are expected to be byte-identical session-over-session — a diff is a red flag that indicates the off-by-default contract has leaked.
