## What This Is

Anukriti Swarm is a **distributed multi-agent pharmacogenomic reasoning platform** that determines whether a medication will work for a patient based on their genetic profile and ancestry. It is a **research system** — not for clinical use.

The core insight: **population is reasoning context, not metadata.** A South Asian patient with CYP2C19*2/*2 (36% carrier frequency) faces fundamentally different risk than a European patient with the same allele (15% frequency). The system makes ancestry a first-class reasoning dimension.

## Architecture Philosophy

Two execution modes with a **hard runtime boundary**:

| Mode | Purpose | Implementation |
|------|---------|----------------|
| **Deterministic** | Phenotype calling, CPIC lookup, allele frequencies, verification, evidence sufficiency rules | Rule tables, closed-enum contracts, `anukriti-pgx-core` library |
| **Generative** | Narrative synthesis, orchestration planning | LLM calls (Gemini primary, OpenAI/Anthropic fallback), guarded by `GenerativeBoundary` |

The `GenerativeBoundary` enforces 4 forbidden actions at runtime: `infer_phenotype`, `override_recommendation`, `bypass_verification`, `fabricate_claim`. The LLM can narrate but never decide.

## Runtime Flow (SwarmRuntime)

```
Input: (drug, gene, population, genotype)
         │
         ▼
Stage 1. Context Assembly  → SwarmExecutionContext (frozen Pydantic)
         │
         ▼
Stage 2. Orchestration     → Planner (Gemini + deterministic fallback) → Router → Coordinator
         │
         ▼
Stage 3. Retrieval         → Multi-strategy retrievers (dense · population-aware · KG · diversity)
         │
         ▼
Stage 3.5. Sufficiency     → SufficiencyCheckpoint (opt-in)
         │                    ├── 6-facet coverage analyzer
         │                    ├── 12-rule decision engine
         │                    ├── 10-rule verifier (SURE-RAG-style)
         │                    ├── 9-rule uncertainty scorer
         │                    └── 3-kind bias detector
         │
         ▼
Stage 4. Verification      → 4 safety engines:
         │                    ├── BiomedicalClaimValidator (shape)
         │                    ├── EvidenceGroundingEngine (existence)
         │                    ├── SafetyConstraintEngine (truth)
         │                    └── ProvenanceValidator (chain)
         │
         ▼
Stage 5. Synthesis         → NarrativeGenerator (guarded by GenerativeBoundary)
         │
         ▼
Output: UnifiedExecutionReport (frozen · 18 fields · JSON-serializable)
```

Every stage emits `RuntimeEvent`s (12 closed `RuntimeEventKind` enum values). The `/ws/run` endpoint streams these live to the frontend.

## Agent Taxonomy

| Agent | Type | Mode | Role |
|-------|------|------|------|
| GeminiOrchestrator | orchestrator | hybrid | Single-entry facade: `run()`, `compare_populations()`, `compare_drugs()` |
| SASPopulationAgent | population | deterministic | South Asian frequency + risk (CYP2C19*2 @ 36%) |
| AFRPopulationAgent | population | deterministic | African frequency + risk (CYP2D6*17 @ 20%) |
| EURPopulationAgent | population | deterministic | European frequency + risk (CYP2D6*4 @ 22%) |
| CYP2D6/CYP2C19/HLA-B | pharmacogene | deterministic | Star-allele interpretation via CPIC |
| Evidence Retrieval | retrieval | deterministic | MA-RAG: query planning + TF-IDF + citation |
| Verification | verification | deterministic | 4-engine composition (6 checks + TAO escalation) |
| ContextSufficiency | verification | deterministic | 4-layer sufficiency (coverage · decision · verifier · uncertainty) |
| Narrative | narrative | generative | Audience-specific reports (clinician/patient/researcher/audit) |

Agents communicate via `AgentMessageBus` (typed pub/sub), `SharedBiomedicalContext` (append-only), and `AgentContextEnvelope` (frozen 7-field messages).

## Key Design Invariants

1. **No clinical decisions** — outputs are research artifacts
2. **Deterministic first** — rule tables always run before any LLM call
3. **Population is reasoning context** — `SuperPopulation` is a first-class closed enum
4. **Every claim has provenance** — `ProvenanceStamp.source_id` required on every KG edge
5. **Off-by-default for new capabilities** — constructor args default to `None`
6. **Every refusal is named** — abstentions cite specific rule IDs (R1..R12, V1..V10, U1..U9)

## Consumer Relationship with pgx-core

`anukriti-pgx-core` owns the deterministic biomedical truth layer. Swarm consumes it via pinned PyPI dependency and re-exports through `rules/phenotype_rules.py`. Version bumps require:
1. Read CHANGELOG for release notes
2. Check CPIC table changes
3. Run swarm regression gate
4. If byte-identical → bump pin; if behavior changed → document + update benchmarks
