### Key design decisions

- **Docker scope is swarm-only.** `anukriti-pgx-core` is a library (no standalone run surface); `anukriti` is a product with its own compose files. Merging all three into one platform-wide compose would force architectural constraints that aren't needed today. See ADR-0001 Alt 4.
- **MongoDB is a separate profile**, not a required dependency. The MCP layer has a genuine in-memory fallback. A new contributor can run the full demo without provisioning MongoDB; someone who wants persistence uses `docker compose --profile mongo up`.
- **Frontend ships via static `python -m http.server` in a separate container**, not baked into the backend image. Zero build step, matches the existing vanilla-JS + D3 choice. If the frontend adopts npm/bundling later, only that container changes.
- **Stack documentation precision matters more than completeness.** The old ARCHITECTURE.md listed "planned" tech next to "actual" tech without distinction. A new contributor would go looking for LangChain code and find nothing. Rewrite describes what's built; a separate line flags the `requirements.txt` orphan declarations as a future cleanup item.
- **ADR framework lives in pgx-core, not swarm.** Platform-wide ADRs need a stable home. pgx-core has the slowest release cadence and the canonical `PROJECT_CONTEXT.md`. A swarm-side `architecture/` directory is fine for design docs (evidence-sufficiency.md, unified-runtime.md etc.) but isn't the right place for decisions that cross the repo boundary.

### Key design decisions

- **Composition, not replacement**. `SwarmRuntime` is a thin sequencer over existing modules. The `ExecutionCoordinator` from `core/orchestrator/` coexists — flagship demos use it, unified demo uses SwarmRuntime. Both are valid paths.

- **Per-request runtime, not per-worker**. Each `POST /api/run` or `WS /ws/run` instantiates a fresh `SwarmRuntime` so event streams don't interleave across concurrent requests. Shared components (KG / indexer / reasoner) are built once per worker via `SHARED_RUNTIME` for warm-start latency.

- **Worker-thread bridge for the WebSocket**. `SwarmRuntime.run` is synchronous (~5 ms). Running it on the event loop would block other connections. `asyncio.to_thread` + `AsyncQueueEventStream` with `loop.call_soon_threadsafe` keeps the event loop free to drain the queue. Fixed a drain-loop-hang bug during phase 3 where `stream.close()` wasn't posting the sentinel after `run()` returned.

- **Backend fields flattened for the UI**. `CheckpointResult.to_dict` originally omitted `coverage_ratio` + `missing_facets` + `uncertain_facets`. Commit 16 added them — additive, backward-compatible. The phase-4 Evidence Sufficiency panel (commit 13) was silently reading `undefined` for coverage before the fix.

- **D3 for the graph view, vanilla JS for everything else**. Approved in the phase-0 brief dialogue. D3 v7.9.0 shipped as a single vendored file (280 KB, MIT); no npm, no build step. Ten closed `NodeKind`s have colour swatches; drag-to-reposition works.

- **Off-by-default persists**. The new live runtime doesn't change the sufficiency-layer's off-by-default contract in `ExecutionCoordinator`. Showcase/safety/interop/evaluation signatures are byte-identical to session #6.

- **Refusals are named**. Every abstention/block/escalation carries a specific rule id (R1..R12 / V1..V10 / U1..U9) surfaced in the UI banner AND the Evidence Gap Analysis. The refusal is a layer, not an erasure — other panels continue rendering their data.

### Lessons from this session

- **Fix the backend response shape when the UI needs it**. The Evidence Sufficiency panel's coverage field read `undefined` for 3 commits (phase 4) before phase 6 needed the same field on the trio runner and I noticed. Additive backend fix unblocked both at once. **Audit the UI contract against the backend response shape during phase review, not only when a new consumer exposes the gap.**

- **Worker-thread + queue is the right pattern for sync-in-async**. The WebSocket drain-loop hang surfaced immediately in the smoke test (14 events then freeze). Fix was to ensure `stream.close()` runs after `run()` returns via an inner coroutine wrapping `asyncio.to_thread`. Worth documenting on the AsyncQueueEventStream class.

- **Frontend-first scope firewall still works**. The UI wants progressive reveal; the backend streams 12 closed event kinds; the frontend binds each kind to a specific panel. ### Key design decisions

- **Collapsed 7 dirs to 2 top-level + 5 subpackages.** Same pattern as session #5. Rationale: a tree of 7 top-level dirs each holding 1-2 files is structurally worse than 2 coherent top-level packages with internal subpackages. Documented at every `__init__.py`.

- **Sufficiency checkpoint is opt-in via constructor, not a config flag.** Flagship demos never pass the argument, never see the new code path. A config flag with a default would invite silent drift; a required constructor arg is explicit.

- **No LLM anywhere in the layer.** Every one of the four rule tables (12 + 10 + 9 + 3) is closed-form arithmetic over structured inputs. Same inputs always produce the same output. Review-time changes only.

- **Population is a first-class node kind in the KG, not metadata.** Weighted edges, first-class closed `SuperPopulation` enum, shared anchor table between analyzer and retriever. The flagship SAS 0.36 CYP2C19\*2 weight is a real KG edge, not a string match.

- **REFUTED vs CONFLICTING is a deliberate distinction.** The verifier can name its refuting signal (AVOID vs USE) and route accordingly; it refuses to pick a side on un-nameable conflicts. Binary pass/fail gates lose this nuance.

- **Off-by-default is a genuine contract.** Verified by running all four flagship demos after every commit and confirming byte-identical signatures. The `.evaluate()` path only runs when the caller constructs a `SufficiencyCheckpoint`.

### Lessons from this session

- **Seed data gap surfaced during smoke-testing.** The initial KG seed lacked `ALLELE → PHENOTYPE` edges, so the flagship `CYP2C19*2 → clopidogrel` scenario had zero traversable paths. Fixed by adding 5 `ASSOCIATED_WITH` edges reflecting the CPIC activity-score rule (commit 11). This is the kind of bug a closed schema makes findable — with a generic KG we'd have silently retrieved *something* plausible.

- **Word-boundary bug in the 3-letter anchor table.** `'eas'` was matching inside `'increased'` in the CPIC clopidogrel content, causing a population-generic doc to be penalised for SAS queries. Fixed by promoting the anchor table to `core/models/population_mentions.py` with `\b`-boundary regex for short anchors (commit 6). Longer phrases like `"south asian"` stay as substring matches — they're unambiguous.

- **Scope collapse documentation matters.** The brief asked for 7 top-level dirs; we shipped 2 + 5 subpackages with the rationale pinned at the top-level `__init__.py`. This is reviewable: a future contributor asking "why isn't there a top-level `uncertainty/`?" gets an immediate answer from the docstring.

- **Opt-in trumps feature flags.** The constructor argument `sufficiency_checkpoint=None` makes the off-by-default contract self-documenting — a reviewer reading the coordinator sees the arg's default and knows immediately that no existing pipeline is affected. A bool flag would have hidden this.
